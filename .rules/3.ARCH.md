# Arch


## 端类型定义

> 具体端的数量与命名由各项目 PRD 定义；下面是通用的端分类模型，供各项目对号入座。

- 系统管理端（SYS）：面向平台运维/管理员，管理全局配置与租户
- 运营端（OPS）：面向平台运营人员，处理运营类事务
- 业务管理端（APP）：面向租户/业务方的管理后台
- 终端用户端（WEB）：面向最终用户的客户端（Web / 移动端）


## 架构通用原则

- **前后端分离**：后端提供 RESTful 接口（见 `3.API.md`），前端独立部署
- **分层**：接口层 / 服务层 / 数据层 职责分离；业务逻辑收敛在服务层
- **无状态服务**：服务端不保存会话状态，依赖 Token 鉴权，便于水平扩展
- **统一鉴权与权限**：集中式鉴权；按端 + 角色 + 数据范围控制访问（RBAC）
- **端路由隔离**：各端有专属路由前缀（如 `/sys/` `/ops/` `/app/` 等，具体见项目路由清单）；专属接口只服务对应端的 token，跨端消费须拆独立接口（细则与反例见 `.rules/3.API.md`「统一接口 + 统一授权引擎约定」）
- **多租户数据隔离**：业务数据按租户 / 实例隔离，查询强制带隔离条件，禁止跨租户越权
- **时区统一**：接口与数据层用 UTC，展示层按客户端时区转换（见 `3.TIMEZONE.md`）
- **国际化**：文案与本地化由请求上下文驱动，不硬编码（见 `3.I18N.md`）


## 逻辑必须闭环

- 每个业务流程必须有完整的开始与结束，不留悬空状态
- 状态流转条件明确，无逻辑跳跃；非法流转必须拦截
- 异常分支（失败、超时、取消、回滚）必须有定义的归属
- 跨端联动的流程，各端状态最终一致
