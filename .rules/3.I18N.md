## 翻译文件交付要求

每个含 UI 文案的版本必须交付**完整翻译文件**，三语齐全、无缺失，与 PRD 页面文案一一对应。

### 翻译文件列定义

| 列名 | 说明 | 示例 |
|------|------|------|
| key | 文案键，命名 `端.页面.元素[.状态]` | `h5.menu.cart.checkout` |
| zh-CN | 简体中文 | 去结算 |
| en-US | English | Checkout |
| ms-MY | Bahasa Melayu | Bayar |
| 所属页面/模块 | 对应 PRD 页面 | 菜单点菜/购物车 |
| 备注 | 占位符、复数、长度限制等 | 含变量 {count} |

### 要求

- **三语必须齐全**：任一语言缺失即视为未完成（联动交付质量门禁「文案完整」）。
- **key 与 PRD 对应**：PRD 页面详述中出现的每条用户可见文案都应有 key。
- **占位符统一**：变量用 `{name}` 形式，三语占位符一致。
- **长度提示**：ms-MY 通常更长，备注标注需注意排版/截断的文案。
- **枚举/状态文案**：状态名、按钮、提示语、空态、错误提示均纳入。
- 翻译文件为开发资源文件（en-US.json / ms-MY.json / zh-CN.json）的来源。

## 多语言数据字段（运行期可编辑，存库）

区别于上面的**静态 UI 文案**（编译期、dev 维护、走 next-intl）：用户可在后台**运行期编辑**的多语言名称/文案（如菜单名、分类名、商品名）随记录**存库**，统一规则：

- **显式 locale 映射存储**：用 `xxx_i18n` JSON，key = locale code（`en-US` / `zh-CN` / `ms-MY`），value = 该语言文案；**`en-US` 必填**（创建/编辑表单校验）。
- **回退统一 en-US**：读取时请求 locale 命中即用，**未命中一律回退 `en-US`**（全局唯一基准语言，钉死不可配）。
- **禁止 `name_default` 这类「默认语言不明」的列**：default 存的是哪种语言无法从数据判断，回退语义不可预测；基准语言必须显式为 en-US。
- 若保留非 i18n 的标量列（如旧 `name`）做检索/排序，须显式定义其语言（= en-US 镜像、写时同步），不得当作语言不明的默认值。

> 备注：现存 `item.name_default` / `item_category.name_default`（v0.2 早于本规则）属待对齐项，触及时按本规则改造（记 `MEMORY.md`）。

## 运行期多语言 · 统一实现（v0.1 ADR-09 + 收口勘误）

> 决策与权衡见 ADR-09 及其**收口勘误**；本节记 what。
>
> **收口（重要，2026-06-30）**：API 动态语言包 / 前端动态路由方案**已删除**（SSR+next-intl 栈上做不到，是 over-build）。定论按文案类型分治：
> - **系统/结构 UI 文案**（菜单/按钮/字段名）→ **前端编译期 bundle**。加一种 UI 语言 = 前端 `config.ts` 加一行 + 加 bundle + **重建**（与代码同生命周期，非缺陷）。
> - **商户业务数据**（商品名/分类名）→ 后端 `name_i18n`（运行期、商户填、零重建）；语种默认对齐前端 3 语，需超出再扩 picker（YAGNI）。
> - **菜单标签**保留 `name_i18n`（admin 运行期管理），不追求跟语言包动态翻译。
>
> ⚠️ 下面凡涉及「S3 语言包 / `/i18n/messages` 运行期加载 / 前端重启即路由 / web bundle 模板生成」的段落**均已作废**。仍有效的只剩：核心规则、`pkg/i18n` 共享件（`Canonical`/`ResolveField`/`BaseValue`/`Parse`/`Marshal`）、`name`+`name_i18n` 数据契约、en-US 基准、搜索 T1。

**一条核心规则**：用户可编辑名称 = `<字段>_i18n` 的 `{canonical: 值}` JSON；读取统一用 `pkg/i18n` 共享 helper 解析（命中请求 locale 即用，否则回退 `en-US`）。**全系统只有一种语言码 = canonical**（`en-US`/`zh-CN`/`ms-MY`/…）；模块报错 i18n 的 locale 文件名亦用 canonical。

- **共享件（禁各模块私有）**：`pkg/i18n` 提供 `Supported()`、`Canonical(in)`（精确→语言前缀→`en-US`）、`ParseField/MarshalField/ResolveField/BaseValue`。`localeMiddleware` 末尾把请求归一化为 canonical 存入 context。新模块一律复用，不得自写 canonical 映射或解析。
- **数据契约**：本地化实体响应恒含 `name`（已解析到请求 locale，显示用）+ `nameI18n`（全 map，编辑回填）；DB 留 `name`（en-US 镜像，供检索/排序/RSQL）+ `name_i18n` TEXT(JSON)，写时 `name = BaseValue(nameI18n)`。
- **基准语言统一 `en-US`**：数据层、模块报错 i18n（`NewModuleI18nFS` fallback）、middleware 默认三处一致。

**语言包（内置 ∪ S3 包）**：
- 内置 `en-US`/`zh-CN`/`ms-MY` 随前后端编译期内嵌（fail-safe）；其他语言 = 语言包，存 S3（`i18n-packs/<locale>/{meta,web,seed}.json`，复用 filestore/ADR-08），启动扫描注册、SYS 可上传热注册/删除（**内置不可删**）。
- `Supported` = 内置 ∪ 已加载包，启动算一次。生效边界：**后端全热**（注册/文案/业务表单即时生效）；**前端 URL 路由**靠 `routing.locales` 启动期取后端 `GET /i18n/locales`，新语种**重启前端进程即路由**（不改码、不重建）。

**完整性（模板不疏漏）以 en-US bundle 为准**：
- 模板三段＝`web`（web app 实际 en-US bundle，`merge(ui, app)`）+ `server`（各 Go 模块 `i18n/locales/en-US.json`）+ `seed`（DB 系统记录 `name_i18n["en-US"]`）；由 web 端实时组装下载（拼自己 web 段 + `GET /i18n/server-template`）。
- CI 门禁以 en-US bundle 为裁判：其他语种/语言包的 key ⊆ bundle、code 引用 key ∈ bundle。缺失运行期回退 `en-US`，且导入 `:validate` 显式报告覆盖率/缺失。
- 翻译交付物**不作运行期完整性来源**（人工制品会滞后于代码；与 ADR-04 一并对齐）。

**搜索**：i18n 字段过滤展开 `(name LIKE ? OR name_i18n LIKE ?)`（`pkg/rsql`，三方言通用、语言包零迁移）；排序走 `name`(en-US) 标量。按语种精确（`json_extract`）/ FTS 按数据规模升级。
