# Design System

> 适用对象：UI / 视觉设计稿。设计稿进入开发前必须通过本规范评审。
> 与 `3.PROTOTYPE.md`（PRD/原型/交互自查）互补：本文件聚焦**视觉与设计系统**。

---

## 设计系统基线

| 维度 | 基线 |
|------|------|
| 间距 | 遵循 4pt / 8pt 体系，统一使用 Design Token |
| 圆角 | 全局统一圆角层级，Token 化 |
| 阴影 | 阴影层级一致，Token 化 |
| 边框 | 边框粗细统一 |
| 色彩 | 主色 / 辅助色 / 功能色（警告/成功/信息）清晰；色阶完整 100–900 |
| 对比度 | 符合可访问性标准（WCAG AA） |
| 字体 | 统一字体体系；字号、行高规范；无字号混乱 |
| 组件 | 优先复用组件库；新增组件需论证必要性 |
| 组件状态 | 每个交互组件含 Default / Hover / Active / Focus / Disabled / Error |
| 主题 | 暗黑模式需重新设计（非简单反色）；大字号不破版 |
| 适配 | 响应式断点明确；Retina / 高分辨率适配 |
| 动效 | 明确 ease / duration；避免过度动效；有动效说明 |

## UI / 视觉设计评审清单

每项逐条核对，不达标即退回。

### 主题与品牌一致性
- 是否符合品牌定位与企业 VI
- 是否延续既有产品视觉基因
- 是否出现风格分叉
- 是否有过度设计（装饰性过强）

### 色彩系统
- 主色 / 辅助色 / 功能色是否清晰
- 色阶是否完整（100–900）
- 是否存在「随意用色」
- 是否符合可访问性对比度标准
- 警告色 / 成功色 / 信息色是否统一

### 复用组件库
- 是否出现重复造轮子
- 是否新增组件（是否必要）

### 状态完整性
- 每个交互组件是否包含：Default / Hover / Active / Focus / Disabled / Error

### 结构规范
- 圆角是否统一
- 阴影层级是否一致
- 边框粗细是否统一
- 间距是否遵循 4pt / 8pt 体系
- 是否使用 Design Token

### 信息层级与排版
- 字体体系是否统一
- 是否存在字号混乱
- 行高是否合理
- 信息主次是否清晰
- 文本对齐是否规范
- 文本截断策略是否清晰

### 页面完整度
- 空状态
- 加载状态
- 异常状态
- 错误提示
- 成功反馈
- 无权限场景
- 数据极值情况（超长文本 / 空值 / 0 值）

### 主题与适配能力
- 是否支持暗黑模式
- 暗黑模式是否重新设计（而非简单反色）
- 大字号模式是否破版
- 响应式断点是否明确
- 是否考虑 Retina / 高分辨率适配

### 交互与动效
- 动效是否有明确节奏（ease、duration）
- 是否存在过度动效
- 动效是否影响性能
- 是否有动效说明文档
- 页面切换逻辑是否连贯

### 可交付成熟度（能否进入开发）
- 是否已标注（尺寸 / 间距 / 颜色）
- 是否整理组件规范页
- 是否命名规范
- 是否图层结构清晰
- 是否有设计说明
- 是否有开发注意事项
- 是否链接可访问（Figma / 蓝湖）

### 可维护性
- 是否增加视觉债务
- 是否影响现有组件库
- 是否需要沉淀为新规范
- 是否与现有版本兼容

### 风险点
- 是否存在性能风险（大图表 / 复杂动画）
- 是否增加前端复杂度
- 是否存在视觉不一致隐患
- 是否存在上线风险

## 管理后台布局与页面骨架规范（Web 桌面后台）

> 适用：**MCH / SYS / OPS** 等 Web 桌面后台（基准 1440×900，最小宽 1280）。**POS/KDS**（Flutter 平板）与**顾客端**（移动 Web）不适用——形态见 CLAUDE.md。本节定义后台**固定外壳(Shell)**与**三类页面骨架（列表 / 表单 / 详情）**；原型与设计稿一律据此搭建，参考实现见 `prototype/mch/`。

### Shell —— 全局固定外壳

布局 = **顶部工具栏(toolbar)** + **左侧菜单(sidebar)** + **内容区(content-area)**。

**顶部工具栏（左 → 右）**：
1. 系统 **LOGO**（最左）
2. **品牌/租户下拉切换器**（紧邻 LOGO 右）：列当前 operator 可管理的租户；下拉**底部分割线之后**多一项「＋ 创建租户」
3. 弹性留白（spacer）
4. **全局搜索条**（含 ⌘K 提示）
5. **语言下拉切换**（zh-CN / en-US / ms-MY）
6. **主题下拉切换**（品牌主题色档位）
7. **明暗模式切换**（light / dark 图标按钮）
8. **个人头像 + 昵称下拉**（最右）：个人资料 / 账号设置 /（订阅账单）/ 退出登录

**左侧菜单（LOGO 下方）**：一级 / 二级两层；二级**可收缩/展开**（点一级组头切换），整条侧栏**可折叠**（折叠态只剩图标）；当前页高亮、所在分组默认展开。**多视角/多端共享导航用统一脚本生成**（如 `sidebar.js`/`sidebar-outlet.js`），不在各页硬编码。

**内容区（菜单右侧）**：顶部**面包屑导航(breadcrumb)**（标当前位置 + 可点上级）；其下为页面主体，按下方三类骨架之一。

### 列表页骨架

自上而下：
1. **筛选工具条**：条件过滤（搜索框 + 若干下拉）+ **[重置]** + **[＋ 添加]** + **[导入]** + **[导出]**；批量操作条默认隐藏、勾选行后浮现。
2. **数据表**：
   - 表头**支持动态显隐列**（列设置菜单）；**每列独立排序三态**（无 → asc → desc，单列生效）；表头 **sticky 吸顶**。
   - 左侧**本地序号列 sticky**（横向滚动不丢失）。
   - **最右操作列 sticky**（查看 / 编辑 / 克隆 / 删除 等）。
   - **行内容为滚动区**（纵向 + 横向滚动）。
3. **表尾 sticky**：总条数 + 分页（每页档位 + 翻页）。
- 口径：**表头 / 序号列 / 操作列 / 表尾 四处 sticky，唯有行内容滚动**。

### 表单系统 —— 增 / 改 / 查 / 克隆 同一套

每个列表项对应 **新增 / 编辑 / 查看 / 克隆** 四页，**复用同一套表单组件与字段 schema**，差异仅在模式：

| 页面 | 模式 | 底部固定操作条（fixed/sticky） |
|------|------|------|
| 新增 | 空表单 | [取消] [提交] |
| 编辑 | 预填当前数据 | [取消] [提交（保存）] |
| 查看（详情） | 编辑页的**只读模式**（字段渲染为只读块、非输入框） | **[编辑]**（切到编辑模式） |
| 克隆 | 编辑页**预填被克隆对象数据**、允许手改后另存为新对象 | [取消] [提交] |

- **查看 = 编辑的只读态，克隆 = 编辑的预填态**——三者同一 schema，禁止各维护一套。
- 底部操作条**始终 fixed/sticky**（长表单滚动时按钮不丢失）。

### 视角(scope)切换

后台支持「品牌/租户」及（多店产品中）「总部/门店」视角切换；**视角切换 = 过滤同一底层数据，不更换页面骨架**（见 ADR-08）。

### 作用域依赖资源的空态门(gate)

当一类资源**必须挂在某个上级作用域下**才有意义（上级作用域由当前视角/切换器确定）时，统一遵守**软引导 gate**，**不硬重定向、不弹窗强拦**：

1. **作用域切换器必选**：列表筛选工具条含作用域切换器，记忆上次选择；列表与新增均限当前作用域。
2. **上级缺失空态**：当前上级作用域下尚无可用上级实体时，依赖资源页显示**空态卡片**——引导先创建上级 + 跳上级新增页按钮；切换器无可选项时禁用 [＋ 添加]。上级建好后正常使用。
3. **上级实体本身可随时创建**：上级列表页不依赖更下级数据，始终可访问、可新增。
4. **顶层作用域缺失**：若登录后顶层作用域（视角根）为空，由 Shell 顶部切换器 +「＋ 创建」承载引导（见上「视角(scope)切换」）。具体哪些资源依赖哪个上级，由各产品 PRD 定义，本规范只定 gate 行为。

## 网络请求 Loading 与并发处理规范

> 适用全部端，**移动端（H5 / POS / KDS / NUM 等 Flutter·App）为重点**。PRD 各页「状态与反馈」遵循本节，不重复定义；联动 `3.API.md` 幂等、`3.TEST.md` 弱网专项。

### Loading 分级

| 级别 | 适用场景 | 形态 | 要求 |
|------|---------|------|------|
| 页面级 | 首屏 / 路由切换后的初始数据 | 骨架屏（优先）/ 全页 spinner | 骨架结构贴近真实布局；禁止白屏 |
| 区块级 | 页面内独立数据区（列表、卡片、统计块） | 区块内骨架 / spinner | 各区块独立加载、独立失败，互不阻塞 |
| 按钮级 | 提交 / 写操作 | 按钮内 loading + disabled | 必须防重复提交（双保险见下表） |
| 列表追加 | 上拉加载更多（移动端） | 列表尾部 spinner | 无更多时显示「没有更多了」并停止触发 |
| 下拉刷新 | 移动端列表刷新 | 下拉指示器 | 刷新完成有明确结束反馈 |

### 防闪烁与超时

- **延迟显示**：请求 < 300ms 完成则不显示 loading（防闪烁）；超过才出现。
- **最短显示**：loading 一旦出现，至少保持 300ms 再消失（防一闪而过）。
- **超时阈值**：读接口 10s、写接口 15s、文件上传 60s；超时转错误态并给「重试」路径。

### 多请求并发处理

| 场景 | 规则 |
|------|------|
| 页面初始化多请求 | 并行发起；各区块独立 loading / 错误 / 重试，单区块失败不拖垮整页；仅首屏关键数据失败才整页错误态 |
| 同源竞态（搜索联想、快速翻页、切 Tab / 筛选） | **以最后一次请求为准**：取消在途旧请求（Web AbortController / Flutter Dio CancelToken），或按请求序号丢弃过期响应；**禁止旧响应覆盖新结果** |
| 重复写操作 | 按钮 loading + disabled（前端）＋ 幂等键（后端）双保险 |
| 全局加载指示（顶部进度条等） | 用**计数器**管理：请求发起 +1、结束 −1、归零才隐藏；禁止任一请求结束就直接隐藏 |
| 依赖型串行请求 | 链路中任一环失败即停止后续请求，在断点处给错误态与重试；禁止带失败数据继续请求 |
| 并发 401 | 多请求同时 401 只触发一次「跳登录」，其余静默丢弃，防止重复弹窗 / 连续跳转 |
| 弱网重试 | 读请求可自动重试 ≤1 次；写请求重试必须由用户显式触发且有幂等键保障（不重单、不重复扣减） |

### 移动端补充

- **连点防护**：所有可触发请求的控件做节流——同一控件 500ms 内重复触发忽略。
- **页面销毁取消请求**：离开页面时取消该页在途请求（Flutter dispose / H5 路由钩子），防止响应回调触达已卸载视图。
- **断网提示**：检测到离线展示全局 banner，恢复后自动消失；POS/KDS 的 MQTT 连接状态组件与本节 HTTP 规范并存、互不替代。
- **上传/下载进度**：超过 3s 的传输必须展示进度（百分比或进度条），不允许只转圈。
