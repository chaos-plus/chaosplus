# TEST


## 测试用例设计方法

每个功能点不能只写 Happy Path。**覆盖原则：每个功能点按本方法把"该覆盖的维度"逐一覆盖完整**——覆盖由方法驱动，不是凑数量。用例总量对任务数的倍率（经验值约 3～5 倍）**仅作覆盖度审计的参考指标，不是硬性目标**：以每个功能点是否覆盖完整为准，不为凑倍率而补、也不为压数量而删。每条用例在「备注」列标注所用方法，便于审计。

### 用例库与执行用途（冒烟 / 回归 / 自动化的关系）

**只有一套功能用例库**。冒烟、回归、自动化不是另写的独立用例，而是对同一套库的不同**选取 / 用途**：

| 用途 | 含义 | 在用例中如何体现 |
|------|------|----------------|
| 冒烟 | 上线前快速跑通的主路径子集 | 用例库中 `冒烟=是` 标记的子集（P0/P1 主流程，单版本 30～80 条） |
| 回归 | 变更后重跑已有用例防止破坏 | **不另存用例**；按变更影响从库中选取重跑（见下「回归分层」L1/L2/L3） |
| 自动化 | 用脚本执行的用例 | 是执行方式，覆盖同一批用例（P0/P1 优先） |

> 因此 `测试类型` 列只表示**用例种类**（功能 / 兼容性 / 压力——这几类用例的设计与环境确实不同），不放「冒烟 / 回归」。是否冒烟用独立的 `冒烟` 列标记；回归不进列。

### 通用方法

| 方法 | 说明 | 取值要点 |
|------|------|---------|
| 等价类划分 | 有效/无效等价类各取代表值 | 有效值 + 每类无效值至少 1 个 |
| 边界值分析 | 取边界及其相邻值 | 最小 / 最小+1 / 正常 / 最大-1 / 最大 / 最大+1；空值 / 超长 |
| 错误推测 | 凭经验构造易错场景 | 重复提交、缺参、非法状态、特殊字符 |
| 组合分析 | 多条件交互 | 多条件过滤、多规格组合、套餐+规格、先付/后付×堂食/外带 |
| 状态迁移 | 业务状态机 | 合法流转逐条 + 典型非法跳转拦截 |

### 项目专项方法

- **弱网与网络异常**：断网 / 弱网 / 高延迟 / 丢包下的下单、支付、长连接（MQTT/WebSocket）重连与状态同步；离线缓存与恢复；POS/KDS 本地直连降级
- **多国语（i18n）**：en-US / ms-MY / zh-CN 文案完整无硬编码；长文案不溢出（ms-MY 通常更长）；日期/数字/货币（SST/GST）本地化；切换即时生效。联动 `3.I18N.md`
- **时区**：接口/存储统一 UTC，展示按客户端时区；跨时区与跨日边界（零点、营业日切分、报表统计区间）。联动 `3.TIMEZONE.md`
- **业务术语一致性**：同一概念在 SYS/OPS/MCH/POS/KDS/H5 各端及三种语言下术语统一（如 订单 / 桌台 / 规格 / 堂食·外带 / 接单 / 整单完成），且与原型、PRD 一致
- **权限与越权（RBAC）**：单端/多端账号、越权访问他端或他店数据被拒、PIN 登录、Token 失效与刷新。联动账号管理
- **并发与幂等**：重复提交不重单、并发接单/改单、库存扣减幂等、支付回调幂等、消息重复消费
- **数据一致性 / 实时同步**：下单 → POS → KDS → H5 跨端数据与状态一致，且在验收时延内更新
- **安全与脱敏**：SQL 注入 / XSS、敏感信息（手机/邮箱）列表与导出脱敏、私有文件鉴权、越权接口
- **异常提示与可用性**：失败有面向用户的明确提示，可重试，不暴露技术细节；loading / 空态 / 错误态完整

### 异常提示规范（验证点）

- 每个失败场景必须有**面向用户的明确提示**，且支持多语言
- 不得暴露堆栈 / SQL / 内部错误码给终端用户
- 网络类异常必须给出「重试」路径
- 表单校验错误需定位到**具体字段**
- 提示文案与 `3.I18N.md` 语言清单一致

### 单功能点展开参考（以「列表」类为例）

> 一个「列表查询」功能点通常应展开为 8～12 条：正常查询、响应体结构、搜索命中、搜索不命中、特殊字符搜索、单/多条件过滤、升/降序、分页首页/末页/越界、每页切换、未登录/越权访问。「新增」展开为：正常、必填校验、唯一性、超长边界、取消、注入防护。「删除」展开为：二次确认、取消、不存在、关联约束。


## 数据层与接口质量测试要点

后端/数据层用例与功能用例并列管理，「备注」列标注对应方法（如 唯一索引 / 幂等 / 性能）。下列基线作为测试标尺，正式标准由后端（开发-后端-SQL）维护。

### SQL / 数据规范校验

| 项 | 基线 |
|----|------|
| 命名 | 表名、字段名统一 snake_case；布尔以 is_ 前缀 |
| 必备审计字段 | `id`（主键）、`created_at`、`updated_at`、`deleted_at`（软删除） |
| 多租户隔离字段 | 业务表含 `tenant_id` / `outlet_id`，查询强制带隔离条件 |
| 字段类型 | 金额用 `decimal` 禁用 `float`；时间统一存 UTC（联动 `3.TIMEZONE.md`） |
| 约束 | 非空、默认值、长度符合定义；枚举值受约束 |

测试点：核对表结构符合上述基线；金额计算无浮点精度误差；软删除后列表不展示但可审计。

### 索引与唯一索引

- 高频查询/过滤/排序字段、外键字段建有索引
- **业务唯一键建唯一索引**（如：门店内桌号唯一、字典 key 唯一、订单号唯一、同租户角色名唯一）
- 测试点：并发/重复插入相同唯一键被唯一索引拦截并返回友好提示（非 500）
- 测试点：无索引导致的全表扫描在压测中暴露（联动压力测试慢查询排查）

### 接口幂等

- 写接口（下单、支付回调、库存扣减、消息消费）支持**幂等键或去重**
- 测试点：同一请求重复提交/重复回调，业务副作用只发生一次（不重单、不重复扣减、不重复入账）
- 测试点：幂等冲突返回与首次一致的结果而非报错
- 测试点：网络重试、超时重发场景下幂等仍成立

### 性能指标（单接口级）

> 区别于系统级压力测试，此处为单接口响应基线，纳入功能/自动化用例。

| 接口类型 | 目标（P95，正常负载） |
|----------|----------------------|
| 列表查询 | ≤ 500ms |
| 详情/单条读 | ≤ 300ms |
| 写操作（新增/编辑） | ≤ 800ms |
| 下单/状态流转 | ≤ 1s（端到端闭环 ≤ 3s） |

测试点：避免 N+1 查询；分页避免深翻页性能塌陷；大字段/列表懒加载。


## 冒烟测试要点定义

冒烟测试在每次迭代上线前执行，覆盖当前版本新增功能的核心主路径，确认基础功能可用后方可进入回归。

### 执行原则

- 仅覆盖 P0/P1 功能的「主流程 Happy Path」
- 单版本冒烟用例控制在 30～80 条
- 执行时间目标：人工 ≤ 2 小时
- 发现 P0 Bug 立即阻断，不进入下一环节

### 冒烟用例字段

| 字段 | 说明 |
|------|------|
| 用例编号 | SMK-{版本号}-{序号}，如 SMK-01-001 |
| 平台端 | 所属应用端（SYS / MCH / POS / KDS / H5 / OPS / WWW / NUM） |
| 一级模块 | 如：订单、登录注册 |
| 功能 | 具体功能点 |
| 测试要点 | 一句话描述要验证什么 |
| 预期结果 | 成功态的判断标准 |
| 优先级 | P0 / P1 |


## 回归测试要点定义

回归测试在每次版本 Release 前执行，确保新改动不破坏已有功能。

### 执行原则

- 覆盖全量已上线功能主路径 + 历史 Bug 修复点
- 重点覆盖跨端联动链路：顾客下单 → POS 接单 → KDS 制作 → 状态回传
- 单轮执行目标：≤ 1 个工作日
- P0/P1 Bug 当天修复、当天复测，通过后方可 Release

### 回归分层

| 层级 | 覆盖范围 | 触发时机 |
|------|---------|---------|
| L1 核心回归 | 扫码→下单→接单→制作→结账 主流程 | 每次 PR 合并后（优先自动化） |
| L2 全量回归 | 全部已上线功能 | 每次版本 Release 前 |
| L3 专项回归 | 变更影响面模块 | 重构 / 架构变更后 |


## 压力测试要点定义

### 目标指标

| 场景 | 目标 |
|------|------|
| 正常负载（单店高峰） | 50 并发用户，P99 响应 ≤ 1s，错误率 0% |
| 峰值负载 | 200 并发用户，P99 响应 ≤ 3s，错误率 ≤ 0.1% |
| WebSocket / MQTT 长连接 | 500 并发连接，稳定保持 30 分钟无断线 |
| 下单闭环吞吐 | ≥ 100 笔/分钟，端到端延迟 ≤ 3s |

### 关键测试点

- API 网关高并发下的响应时间与错误率
- MQTT 长连接在峰值下的稳定性（POS ↔ KDS ↔ H5）
- 高并发下的订单状态一致性（不丢单、不重单、不乱序）
- 数据库连接池在峰值下的表现与慢查询情况


## 自动化测试要点定义

### 覆盖策略

| 类型 | 工具建议 | 覆盖目标 |
|------|---------|---------|
| API 接口自动化 | Postman Collection / RestAssured | P0/P1 接口 100%，P2 接口 ≥ 80% |
| 前端 E2E | Playwright | 核心下单闭环主流程 ≥ 5 条 |
| 单元测试 | JUnit + Mockito | Service 层核心业务逻辑 |
| CI 集成 | GitHub Actions | PR 合并前自动触发 API 测试 + 单元测试 |

### 准入标准

- 新功能上线前，P0 流程必须有对应自动化覆盖
- 历史 P0 Bug 修复后需补充自动化回归用例
- API 层自动化覆盖率目标：≥ 80%


## 兼容性测试要点定义

兼容性测试在每次涉及 UI/前端的版本 Release 前执行，确认产品在目标市场（马来西亚/新加坡）主流屏幕、设备、系统版本上展示与交互正常。

### 执行原则

- 覆盖各端目标设备矩阵的主流程 + 关键页面渲染
- 优先覆盖目标市场占有率 Top 机型与系统版本
- 同一用例在不同设备/版本上复用，差异以「应用平台端 + 备注(设备/版本)」区分
- 渲染类问题以截图留证

### 屏幕响应式

| 端 | 断点 / 适配要求 |
|----|----------------|
| SYS / OPS / MCH（WEB 后台） | ≥1920 / 1440 / 1366 / 1280；最小宽度 1280，低于此出现横向滚动而非错版 |
| 官网 WWW | PC（≥1280）/ 平板（768–1024）/ 手机（≤480）三档自适应 |
| H5 顾客端 | 320–480 主流手机宽度流式布局；横竖屏；折叠屏展开/收起 |
| POS / KDS | 平板横屏为主（如 1280×800），适配不同平板分辨率 |

### 屏幕兼容性

- 分辨率与 DPI/缩放（100% / 125% / 150%）下不破版
- 长宽比与安全区：刘海屏 / 挖孔屏 / 圆角，内容不被遮挡
- 横竖屏切换：POS/KDS 锁定横屏；H5 跟随系统
- 大屏：NUM 叫号显示屏（1080p / 4K、竖装吊屏场景）字号与队列清晰可读
- 暗黑模式 / 系统字体放大下布局不溢出、不重叠

### 设备兼容性

| 类别 | 覆盖范围 |
|------|---------|
| 手机（H5） | iOS / Android 目标市场主流机型各 Top3–5 |
| 平板（POS / KDS） | iPad + 主流 Android 平板各 ≥2 款 |
| 外设 | 蓝牙 / 网络小票打印机、钱箱、扫码枪 / 摄像头扫码 |
| 叫号（NUM） | 显示屏（Android 大屏 / 电视盒子）+ 手持取号设备 |

### 系统版本兼容性

| 平台 | 覆盖版本 |
|------|---------|
| iOS | 最新及前 2 个大版本（如 iOS 16 / 17 / 18） |
| Android | API 26+（Android 8.0 起），覆盖最新及主流版本 |
| 浏览器（WEB / WWW） | Chrome / Safari / Edge / Firefox 最新及前 1 版 |
| 移动浏览器（H5） | 移动端 Safari / Chrome / 微信内置 WebView |
| Flutter App | 明确最低支持 SDK 与目标 SDK，覆盖内嵌 WebView 组件版本 |

### 关键测试点

- 各端核心页面在目标矩阵无错版、无溢出、无重叠、图片不变形
- H5 在微信 / Safari / Chrome 内置浏览器下扫码跳转、支付回调正常
- POS / KDS 在目标平板上 MQTT 长连接与打印外设稳定
- 不同系统版本下日期 / 时区 / 数字 / 货币（SST/GST）本地化显示正确（联动 `3.I18N.md` / `3.TIMEZONE.md`）


## 交付质量门禁（提测 / 发布前检查）

功能进入提测、以及版本发布前，逐项核对；任一项不通过则阻断交付。

### 一致性验收

| 检查项 | 标准 |
|--------|------|
| 需求文档 | 功能实现是否**完全匹配需求** |
| 原型图 | 功能流程是否**完全匹配原型** |
| UI 设计稿 | 页面效果是否**完全还原设计**（联动 `3.DESIGN.md`） |

### 代码质量

| 检查项 | 维度 | 标准 |
|--------|------|------|
| 代码走查 | 静态检测 + 人工检测 | 代码实现是否符合设计规范 |
| 代码审计 | 安全漏洞 / 合规问题 / 架构风险 / 发布风险 | 是否引入新的问题或潜在风险 |

### 范围与测试结论

| 检查项 | 标准 |
|--------|------|
| 迭代清单 | 迭代清单内事项已完成；**无迭代清单外事项**（如有须说明并评审） |
| 提测测试报告 | 提测 BUG 率 **< 5%** |
| 回归测试报告 | 回归测试**全部通过** |
| 交付前置检查表 | 检查清单**全部通过** |


## 测试用例文档格式定义

### 测试用例字段定义

| 列名 | 类型 | 说明 | 示例 |
|------|------|------|------|
| 用例编号 | string | TC-{端缩写}-{版本}-{序号} | TC-H5-01-001 |
| 测试类型 | enum | 功能 / 兼容性 / 压力（用例**种类**，非执行用途） | 功能 |
| 应用平台端 | string | 所属端 | 顾客端 |
| 一级模块 | string | — | 菜单点菜 |
| 二级模块 | string | — | 购物车 |
| 功能 | string | 具体功能点 | 下单/结算 |

### 文件组织

测试用例按用例种类分文件管理。功能用例含冒烟标记，随功能交付必做，冒烟与回归从此库选取。兼容性、压力单独管理：二者不随每个版本必做（尤其压测时常跳过），且只在确有此类用例时创建。三套用例共用同一套 15 列字段；冒烟是标记列，回归不单独存（按变更影响从功能库重跑）。
