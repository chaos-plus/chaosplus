# Backend Engineering Contract

This file is the canonical backend contract for every supported coding agent.
Agent-specific skills are runtime adapters only and MUST reference this file
instead of copying these rules.

## Pre-code gate

- Before any write, search the whole repository for the domain, public symbols,
  routes, tables, configuration, constructors, lifecycle hooks, tests, callers,
  and consumers that may already own or constrain the change.
- Read the complete relevant owner implementation and one production module of
  comparable shape. For IAM/security work, trace authentication, authorization,
  trusted claims, tenant/entity membership, repository scope, audit, migrations,
  and every affected client end to end.
- Publish the final-state design with these headings before editing:
  `Requirement/Invariants`, `Repository Searches`, `Inspected Owner/Consumers`,
  `Existing Owner Capability`, `Verified Gap`, `Final Ownership`,
  `Dependency/Composition`, `API/Data/IAM Contract`,
  `Failure/Migration/Rollback`, and `Acceptance Gates`.
- Search first, design second, code third. A missing search, unread owner, unproved
  gap, temporary destination, compatibility staging package, or incomplete final
  design blocks every write.

## Ownership and DDD

- `apps/server/internal/app` is the shared composition, Huma, database, IAM,
  security, GUID, configuration, and lifecycle owner. `apps/server-ai` consumes
  that host and contains only AI product modules and their composition.
- Each bounded context is an independently wired `internal/modules/<domain>`
  module and owns domain, service, repository, REST, migration, three-dialect
  SQL, i18n, lifecycle, and tests. A product area containing aggregates with
  different state machines or lifecycles MUST be split into leaf modules; its
  parent package may only coordinate them through narrow application ports.
- A leaf module MUST contain `module.go`, `domain.go`, `service.go`,
  `repository.go`, `rest.go`, `migrate.go`, `i18n.go`, `sql/sqlite`,
  `sql/mysql`, `sql/postgres`, and `i18n/locales/{en-US,zh-CN,ms-MY}.json` when
  those capabilities apply. Do not centralize module persistence or locales.
- Production filenames describe domain roles, not implementation libraries.
  Prefixes such as `bun_`, `huma_`, `goose_`, `sqlc_`, and `http_` are forbidden.
- Never introduce a shared business `internal/store`, central feature server,
  sqlc, RSQL, duplicate auth/security/database/ID packages, or an embedded
  infrastructure daemon.

## Persistence

- Goose owns migrations. Bun owns ORM, queries, and transactions. Construct one
  `*bun.DB` in the shared host and inject it into modules.
- Every internally generated entity/resource/event ID and every internal FK uses
  `guid.ID` and SQL `BIGINT`, including tenant, entity, owner, principal, creator,
  updater, and deleter. Generate through the shared leased Sonyflake lifecycle.
  Encode IDs as decimal strings at JSON/HTTP/NATS/JavaScript boundaries.
- Store instants as UTC Unix milliseconds in `BIGINT`; convert timezone only in
  presentation. Store durations as bounded integer milliseconds.
- Mutable aggregates explicitly define tenant/entity scope, owner, creation and
  update audit, deletion policy, and optimistic version. Ownership is not audit.
- Use typed Go enums plus service validation and equivalent DDL `CHECK`
  constraints. Use real booleans and validated JSON. Do not encode IDs, time,
  enum, boolean, money, or structured domain state in arbitrary text.
- Every persistent leaf module has schema-equivalent SQLite, MySQL, and
  PostgreSQL Goose migrations, including equivalent PK/FK types, nullability,
  checks, unique constraints, indexes, audit/delete/version fields, and Down.

## API, IAM, and infrastructure

- Use Huma through the shared application host. Business modules do not mount a
  separate `http.ServeMux` or duplicate response/security middleware.
- Authentication and authorization are deny-by-default, including reads. Trust
  only shared verified claims. Repository predicates always enforce tenant and
  entity scope; never persist client-supplied identity or ownership selectors.
- Development and production NATS use the fixed official image. Preview tunnels
  use official FRP: separately deployed `frps`, runner-supervised `frpc`, and an
  IAM-aware public gateway. Do not embed either service or use Cloudflare Tunnel.

## Delivery

- Run architecture and schema contracts before structural work, after it, and
  before delivery. Run affected three-dialect migration tests before Go tests.
- Run formatting, race, vet, static analysis, vulnerability checks, frontend
  lint/typecheck/tests/build, responsive browser acceptance, and real protocol
  checks proportional to the change. Never claim an unrun environment passed.
- Commit and push only after every applicable gate passes and the complete
  worktree has been reviewed for unrelated changes.
