# 接口定义

## 严格使用 RESTFUL API 定义

- 资源用名词（复数），层级清晰；动作通过 HTTP 方法表达，不在 URL 用动词
- 方法语义：GET 查询 / POST 新建 / PUT 全量更新 / PATCH 局部更新 / DELETE 删除
- 请求与响应统一 JSON，UTF-8 编码

## 请求头

- 语言（决定返回文案语言，联动 `3.I18N.md`）
- 时区（展示层时区，接口/存储统一 UTC，联动 `3.TIMEZONE.md`）
- 鉴权：`Authorization: Bearer <token>`

## 统一响应体

- code：纯数字（0=成功；非 0 见各版本「业务码总表」）
- message：面向调用方的提示（支持多语言）
- meta：分页等元信息（如总数、页码、每页条数）
- data：业务数据

**业务结果一律 HTTP 200**：成功与业务错误都返回 HTTP 200，由 body `code` 区分；HTTP 4xx/5xx 仅用于到不了业务逻辑的层（网关 / 鉴权 / 路由 / 限流 / 基础设施）。

**业务码分段**：`0` 成功；`1–99` 系统通用错误（业务无关）；`100–999` 对齐 HTTP 语义的通用失败（无专属业务码时）；`1000–99999` 保留；`≥100000` 业务专属码＝`1·模块2位·序号3位`（6 位，可升 7/8 位扩展），**同一业务错误跨端同码**。各版本码表为该版本单一来源（见 PRD「业务码总表」）。决策见 ADR-09。

## HTTP 状态码语义

> 业务结果走 HTTP 200（见上「统一响应体」）；下表状态码用于**传输 / 网关 / 基础设施层**。业务的「校验失败 / 冲突 / 无权限 / 不存在」等语义改由 body `code` 表达（见各版本业务码总表）。

| 状态码 | 含义 |
|--------|------|
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 / Token 失效 |
| 403 | 已认证但无权限 |
| 404 | 资源不存在 |
| 409 | 冲突（如唯一键重复） |
| 422 | 校验不通过 |
| 500 | 服务端错误 |

## 多租户作用域鉴权（决策见 ADR-10）

适用于 operator/tenant 解耦后的业务端；系统管理端（SYS）Token 不含 tenant 作用域，两套互不兼容。

- **JWT payload 自包含**：`operator_id` + `tenant_id` + `scope`（`tenant`/`instance`/`all_instances`）+ `instance_id`（scope=instance 时必填）。
- **tenant_id 服务端签发**：登录或切换 tenant 时，服务端从 `operator_tenant` 查询授权后签发进 token；**禁止信任客户端 Header 传入 tenant_id**；切换 tenant 须重新签发 token。
- **instance 作用域传递**：经请求头 `X-Scope-Instance-Id: <instance_id>` 传递；鉴权中间件每次请求校验该 instance 属于 token 中 tenant 且 operator 有权访问（`operator_tenant.accepted_at` 非空、role 有效），越权返回 403。
- **写操作作用域约束**：`scope=all_instances` 或缺作用域时，写操作返回 400/403（只读视图不可写）。
- **数据隔离**：所有租户范围查询从 token 解析 tenant_id 作隔离条件，不从请求体接收；同 tenant 内不同 instance 仅可读写本 instance 数据，跨 instance 访问 403。

## 通用约定

- **分页**：统一分页参数与返回，列表响应在 meta 返回总数，便于前端分页
- **鉴权**：无状态 Token 鉴权；越权访问返回 403，未认证返回 401
- **幂等**：写操作（创建、异步回调、状态变更等）支持幂等，重复请求不产生重复副作用
- **时间**：传输与存储用 UTC，时间格式统一（ISO 8601）
- **错误**：错误通过 code + message 表达，不向调用方暴露堆栈或内部细节
- **校验**：参数校验失败返回明确字段级错误信息

## 统一接口 + 统一授权引擎约定（现行架构）

> 本节取代早期「各端路由隔离」约定。历史规约要求每个端拆独立接口；现行架构是
> **一套共享接口 + 一个统一授权引擎按数据区分平台/角色/产品/订阅**（决策与分阶段落地、
> 现状差距、迁移证据详见 该文档已迁移至内部知识库）。

### 核心原则

**业务 CRUD 是共享的一套接口**，挂在 `/api/v1` 裸路径下，由**统一授权引擎**（`pkg/authz` PDP）判定，
调用方属于哪个端由 **token + 权限码 + 资源归属**区分，不为每个端复制接口。引擎在一个决策点组合：

1. **RBAC**：权限码 `resource:action`（通配 `httpx.MatchPermission`）；
2. **归属**（ABAC）：资源的 owner-scope（platform/tenant/instance），**scoped 主体永不能写平台资源、跨租户不可见**（`authz.Authorize`）；
3. **订阅 entitlement**：`humax.RequireFeature("feature.X")` 与权限 **AND**，按租户套餐门控（缺功能 → 402 `FEATURE_NOT_ENTITLED`）。

一套码即可：例如 `/roles` CRUD 由单一 `roles:*` 服务系统管理端与业务管理端，引擎把业务端调用者限制在本租户角色
（早期按端拆分的双码族已退休）。

### 仍保留端前缀的接口（语义确不同，非重复）

| 类别 | 前缀 | 原因 |
|------|------|------|
| 登录/会话 | `/{端}/auth/*` | 凭据类型不同（如密码 vs API Key），签发不同 token |
| 平台专属配置 | `/sys/configs/*`、`/sys/captcha/*`、`/sys/dicts`、`/sys/{email,sms}/test` | 单端运维，无跨端面 |
| 业务端专属 | `/app/tenant`（自身信息）、`/app/scope/switch`（ADR-10 切实例）、`/app/subscription`、`/app/billing/*` | 业务端语义 |

**菜单树保留两个接口**：`GET /menus/tree`（系统管理端目录管理视图，需 `menus:read`，返回全量含隐藏）与
`GET /app/menus/tree`（业务端导航视图，按操作员角色 `role_menus` 过滤，无需 `menus:read`）—— 经复核二者是
**不同操作**（目录管理 vs 角色导航），非重复，故不合并。tenant/instance 两视角在 `/app/menus/tree` 内由 `scope`
参数（signed token scope）区分，已是单接口。

### 硬性约束（违反须返工）

1. 业务接口默认共享、走统一引擎；**不得**为每个端复制业务 CRUD 接口。
2. **禁止**：某端 token 因缺另一端的权限码而被拒（典型症状：侧边栏因 403 被静默吞掉而空白）——
   统一码 + 按端/角色的授权（seed 授予对应角色）保证各端 token 持有其所需码。
3. 新增受控资源必须在 `internal/app/authz_resources.go` 声明 owner-scope（覆盖门测试 `TestRegisterAuthzResources` 强制）。
4. 新增付费产品 = 插 `features`/`plan_features` 数据行 + 端点加一个 `feature("feature.X")` 注解，**0 新接口**。

## 列投影与导出约定

### DB 级列投影（`?fields=`）

列表接口支持 `?fields=col1,col2` 参数，后端在 SQL `SELECT` 层直接投影，减少网络与内存开销：

- 字段名经白名单过滤（`httpx.BuildColumnMap(ResponseDTO{})` 注册允许列），禁止拼接用户原始输入
- 未填 `fields` 或全部非法时，返回全列
- 投影列必须包含 `COUNT(*) OVER() AS __total` 以支持分页总数
- 实现参考：`internal/goods/repository.go` → `ListProjected` + `goodsColMap`

### 后端驱动导出（禁止前端处理数据）

所有导出接口（xlsx/csv）必须由后端 API 完成，前端只负责触发下载：

- **禁止**前端 fetch 全量数据后在浏览器内生成文件（内存 OOM、token 暴露、数据量限制）
- 后端导出支持 `?columns=col1,col2` 参数按需筛列；`columns` 为空时输出全列
- 大数据量（>10万行）必须分段读取（`LIMIT chunk OFFSET n` 循环）再流式写入响应，避免一次性全量 query
- 响应头：`Content-Type: application/octet-stream`，`Content-Disposition: attachment; filename="xxx.xlsx"`
- 实现参考：`internal/dict/service.go` → `Export` + `dictExportCol`；导出 handler 使用 Gin 原生响应（`c.Header` + `xlsx.Write(c.Writer)`）

### 字段安全原则

所有用户传入的字段名/列名参数（`fields`、`columns`、`sort`）必须经过白名单过滤，不得直接拼入 SQL：

```go
// 安全：经 BuildColumnMap 白名单过滤
cols := httpx.FieldsToColumns(in.Fields, goodsColMap)

// 禁止：直接拼用户输入
query := "SELECT " + in.Fields + " FROM goods"  // ← SQL 注入
```
