# ADR 决策记录规范

> ADR（Architecture / Any Decision Record）记录「**为什么这么定**」——选型、方案权衡、规范变更、业务模型决策。PRD 记「是什么」，ADR 记「为什么」，互链不复述。
> **记录按版本存放，各版本各记各的**：每个版本一个 `adr.md` 单文件；本文件只定义规范，不存记录。

## 何时必须写

满足任一条即写：

| 触发 | 示例 |
|------|------|
| 技术 / 方案选型（≥2 个可行方案做了取舍） | 原型用 HTML 还是 SVG/Excalidraw（v0.2 ADR-02） |
| 推翻或修改既有规范 / 约定 | 克隆从独立接口改为纯前端行为（v0.1 ADR-01） |
| 影响多版本 / 多端的业务模型 | 桌台会话模型（v0.2 ADR-03） |
| 安全 / 锁死 / 不可逆风险的权衡 | 验证码配置防锁死（v0.1 ADR-02） |
| PRD「待确认默认值」被**调整**（非沿用） | 如上传限制 10MB 改为其他值 |

**反例（不写）**：常规功能细节（写 PRD）、排版修订、bug 修复、沿用默认值的确认（在 PRD 待确认清单标记即可）。

## 存放与编号

- 记录文件：`adr.md`，**每版本一个单文件**（该版本没有决策就不建此文件）。
- 编号：版本内递增 `ADR-{两位序号}`；跨版本引用写全称，如 `v0.2 ADR-03`。
- 归属：决策记在**做出该决策时所在的版本**；影响范围在元信息标明（仅本版本 / 后续版本起 / 全局）。
- **全局性决策**：ADR 记权衡与为什么，规则本体仍沉淀到对应规范文件（`.rules/` 或 CLAUDE.md）——**ADR 记 why，规范记 what**，两边互链。
- 文件结构：顶部索引表（编号 / 标题 / 状态 / 影响范围 / 日期）+ 按编号追加的记录正文；**新增记录必须同步索引表**。

## 状态与不可变纪律

- 状态机：`提议` → `已采纳` → `已废弃` / `被 {全称} 取代`（未列出的迁移非法）。
- **append-only**：「已采纳」的记录不改写正文——决策变了写新 ADR 取代旧的、新旧双向引用，旧记录只改状态行；「提议」状态可修改正文，确认后改「已采纳」。

## 与 MEMORY / PRD 的分工

- `MEMORY.md`：只留一行指针（一句话 + 全称编号），不展开正文。
- PRD：更新记录与相关章节引用编号（同版本写 `ADR-{NN}`，跨版本写全称）；ADR 不复述 PRD 细节，只链接（章节 / R{n} / TC 编号）。

## 记录模板

```markdown
## ADR-{NN} {标题：一句话说清决策}

> 日期：{YYYY-MM-DD} | 状态：{提议 / 已采纳 / 已废弃 / 被 {全称} 取代} | 影响范围：{仅本版本 / 后续版本起 / 全局}

**背景与问题**：{为什么必须做这个决定；约束；触发事件}

**备选方案与权衡**：

| 方案 | 优点 | 缺点 / 成本 |
|------|------|------------|
| A {…} | | |
| B {…} | | |

**决策**：{选了哪个——一句可判定的话 + 关键参数；提议状态须列待确认点}

**后果**：正面 {…}；负面/代价 {…}；需要执行 {…}

**关联**：{PRD 章节 / R{n} / TC / 规范文件 / 相关 ADR}
```
