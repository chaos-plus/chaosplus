# PROTOTYPE

> 适用对象：PRD / 原型图 / UI 设计稿。三者交付（进入开发）前必须通过本规范自查。
> 评审范围以**本期版本范围**为准（见对应 `prd.md`）。

---

## 设计要点

每个页面/功能在设计阶段必须明确：

- **范围边界**：本期做什么、**不做什么**（明确划清，避免开发自由发挥）
- **全状态覆盖**：每个页面定义 默认 / 空态 / 加载中 / 错误态 / 极端值（超长文本、超大列表、0/负数、最大值）
- **流程闭环**：状态流转条件完善，无逻辑跳跃；非法流转有拦截
- **多语言就绪**：所有文案走 i18n，预留长文案空间（ms-MY 通常更长），无硬编码（联动 `3.I18N.md`）
- **设计系统一致**：色彩/字体/间距/组件遵循 `3.DESIGN.md`
- **术语一致**：同一概念跨端（SYS/OPS/MCH/POS/KDS/H5）与跨语言术语统一
- **无模糊表达**：不出现「应该 / 一般 / 尽量 / 可能」等模糊措辞，需求必须可判定
- **时区选择器**：含时区字段的表单必须使用「带建议值必选 + 检测提示」模式（见 `3.TIMEZONE.md`「时区选择器 UI 约定」）；禁止「跟随系统」选项；预填值显示时需配固定说明文案「影响报表时间和营业时间判断，请确认」

## 生成要点

- 覆盖上述全部状态，不只画 Happy Path
- 使用接近真实的数据（含边界数据），不用「示例示例」占位
- 关键交互标注流转条件与异常分支
- 涉及权限的页面标注不同角色/端的可见与可操作差异

## 设计评审自查清单

PRD / 原型 / UI 每个功能点逐项回答；标注「无」也是有效答案，但不可留空。

| 维度 | 检查标准 |
|------|---------|
| 本期范围 | 明确本期实现内容 |
| 不做范围 | 明确本期**不做**的内容，划清边界 |
| 灰度策略 | 无 / 具体灰度规则 |
| 流程闭环 | 状态流转条件完善，无逻辑跳跃 |
| 异常覆盖 | 空态、极端值、错误提示语完整 |
| 操作记录 | 操作是否需要记录、可溯源 |
| 删除保留 | 删除数据是否保留（逻辑删 / 物理删） |
| 权限规则 | 数据隔离性等清晰完整（端/角色/租户/门店） |
| 计算逻辑 | 是否精确（金额、税 SST/GST、库存扣减、折扣） |
| 校验规则 | 文本长度 / 类型限制 / 特殊字符 / 正则 / 数值上下限 是否明确 |
| 文案完整 | 多语言翻译齐全（en-US / ms-MY / zh-CN） |
| 配置来源 | 硬编码 / 开发配置 / 运维配置 / 用户配置；是否常变；是否多语言；是否枚举 |
| 状态覆盖 | 是否存在未定义或不明确状态；默认状态是否明确 |
| 影响核心流程 | 否 / 影响范围 |
| 影响历史数据 | 否 / 影响范围 + 迁移说明（up / down） |
| 是否依赖三方 | 否 / 依赖范围 |
| 版本兼容 | 无影响 / 兼容升级 / 强制升级 |
| 逻辑冲突 | 无 / 与已有功能的冲突点说明 |
| 可测试性 | 能写出完整测试用例 |
| 模糊描述 | 无「应该 / 一般 / 尽量」等模糊表达 |

## 检查要点（评审结论）

- 任一维度留空 → 退回补充，不进入开发
- 「计算逻辑 / 校验规则 / 状态覆盖 / 权限规则」存在歧义 → 必须澄清后再开发
- 「影响历史数据」为是但无迁移说明 → 阻断
- 「可测试性」为否 → 说明需求未达可开发标准

## PRD 写作规则（三读者）

> PRD 同时服务三个读者：**人**（评审业务正确性）、**AI**（生成生产代码）、**测试**（生成测试用例）。满足「PRD 文档结构」只是底线，逐条内容还必须满足以下写法；任何一条不满足，自查清单「可测试性」即为否。

### 1. 可判定性

- 每条需求可判真伪：禁止「应该 / 一般 / 尽量 / 可能 / 等 / 约 / 合理」；
- 枚举一律**闭集**（列全所有取值，不写「等等」）；默认值显式声明；
- 数值给完整边界：min / max / 步长 / 单位 / 精度 / 舍入规则（金额联动 `3.TEST.md` decimal 基线）；
- 时间声明判定基准（服务端 UTC 判定 / 客户端时区展示）与边界含否（如「≤ 2h（含）」）。

### 2. ID 可追溯体系（贯穿 PRD ↔ 原型 ↔ 任务 ↔ 用例 ↔ 代码）

| ID | 含义 | 定义处 | 被引用处 |
|----|------|--------|---------|
| `P{n}` | 页面 | 分端 · 页面清单 | 原型文件、用例 |
| `G{n}` / `C{n}` | 全局 / 局部组件 | 分端 · 全局组件 / 组件清单 | 原型 `data-comp` |
| `A{n}` | 接口 / MQTT / 任务 | 分端 · 接口详述 | 组件数据来源、操作清单、用例 |
| `R{n}` | 业务规则 | 总览 · 业务规则 | 各端页面、状态机、用例备注 |
| `SM-{对象}` | 状态机 | 总览 · 状态定义 | 业务流程、接口错误码、用例 |

同一规则只在定义处写一次，其余位置**只引用 ID 不复述**（防止两处不一致）。

**引用 ID 时必须带简短标签,全文零裸编号**（读者无需跳回定义处，「全括，避免歧义和心智负担」）：
- 形如 **`ID（简短标签）`**：`R19（POS开台代点）`、`A3（提交订单）`、`P2（订单工作台）`、`G6（二次确认弹窗）`、`C6（操作按钮组）`、`SM-order 20（已下单锁定）`；标签用**定义处的规范短名**（≤8 字），全仓一致、禁止同一 ID 出现不同标签（漂移即缺陷）。
- **范围全覆盖,无例外**：P/G/C/A/R 全部；**包括**表格里「点 C6」这种同页局部组件引用、「调用接口：A2、A3」清单、异常表定位列、坐标式 `P2.C7`（写成 `P2（订单工作台）.C7（退菜弹层）`）、流程图/时序图节点（含页面 P）。**C 编号跨页重复，按引用所在页的组件清单取名。**
- **数字枚举状态一律配语义名**：订单/会话/桌台状态、业务码等凡以裸数字出现处,写成 `数字（语义名）`,如 `status=20（已下单锁定）`、`桌台 4（待清台）`、`code 403（无权限）`、`item_status=1（待制作）`。
- 已是 `标签（ID）` 顺序（如「退菜（R22）」「催单 R17」）即视为合规,不必再套一层。
- **保留裸 ID 仅限两类**：① 各定义表（页面清单/全局组件/各页组件清单/接口详述）的**第一列 ID** 与状态机迁移表的**「值」列**（定义位本身）；② **跨文档 A 引用**（指向别端 A 编号空间，只标归属如「契约见 prd-mch.md A1」，不套本端名以免误指）；③ 带花括号的记法占位 `P{n}`/`C{n}`/`R{n}`、版本引用 `R1`、用例号 `TC-*`、验收号 `AC*`、状态机名 `SM-*`。
- mermaid 状态图节点用 `state "10 待接单" as S10` 去 `S` 前缀。

### 3. 规则用表格，不用散文

- **校验规则** → 表格：字段 / 类型 / 必填 / 长度·值域 / 格式·正则 / 错误提示 key；
- **计算逻辑** → 公式 + 精度与舍入 + **至少 1 组数字示例**（其中 1 组取边界值）；
- **状态机** → 迁移表（当前态 + 触发 + 条件 → 目标态 + 副作用）；**未列出的迁移一律非法**并声明拦截行为（错误码 + 提示 key）；
- **接口** → 契约表（方法 / 路径 / 鉴权 / 幂等 / 入参 / 出参 / 错误码），响应遵循 `3.API.md` 统一响应体。

### 4. 行为三段式

每个用户操作写满三段：**触发**（谁在什么前置下做什么）→ **结果**（数据变化 + 用户反馈，确定性）→ **异常**（每个失败分支：错误码 → 提示 key → 用户去向）。只写 Happy Path 视为未完成。

### 5. 测试可推导性（PRD 合格的标尺）

- 校验规则表 → 直接推导等价类 / 边界值用例；
- 状态机迁移表 → 直接推导合法迁移 + 非法拦截用例；
- 操作清单异常列 → 直接推导错误推测用例；
- 验收标准量化（时间 / 并发 / 数量）→ 直接转性能断言；
- **反向检验**：任取一条规则，问「能否不加追问写出用例」——不能则该条没写清。

### 6. 人审友好

- 总览在前讲业务（目标 / 范围 / 术语 / 流程），精确表格下沉到分端；
- 流程与状态机配 mermaid 图：**人看图、AI 读表**，两者并存且必须一致；
- 每页配原型 iframe 对照（`prototype/{端}/`，同级相对路径，无 `../`）。

## PRD 文档结构

每个版本的 PRD 按以下结构组织。**多端版本拆分为「总览 + 分端」多文件**（`prd.md` + `prd-{端}.md`）；单端大版本可按模块拆；小版本单文件。**模板见 `4.PRD_TEMPLATE.md`，新写 / 重构一律从模板起步。**

### 总览文档 `prd.md`

1. **更新记录**：版本 / 日期 / 修改人 / 说明（表格，倒序）
2. **版本目标**：含可量化成功标准
3. **范围边界**：本期范围 / 不做范围（推迟项标注去向版本）
4. **术语表**：术语 / 英文·代码名 / 定义（统一跨端、跨语言、跨 DB 命名）
5. **角色与权限**：端 / 角色 / 数据范围（租户 / 门店隔离）
6. **数据模型**：每表字段·类型·必填·默认·约束·索引·唯一键（遵循 `3.TEST.md` SQL 基线）
7. **状态定义**：每个有状态对象一个状态机 `SM-{对象}`（枚举表 + 迁移表 + mermaid 图；未列出的迁移一律非法）
8. **业务流程**：仅**跨端联动**流程（标注端与交接点、异常分支）；端内流程下沉对应分端第 2 节；单端版本标注「无跨端流程」并指向分端
9. **业务规则**：跨页面共享规则的单一来源（`R{n}` 表：规则 / 量化定义 / 关联 ID）
10. **数据与影响面**：影响核心流程 / 影响历史数据 + 迁移说明（up / down）
11. **依赖与兼容 / 灰度策略 / 逻辑冲突**
12. **验收标准**：量化指标（指标 / 目标值 / 测量方式）
13. **分端 / 分模块文档索引**
14. **版本级设计自查清单**（见上「设计评审自查清单」20 维度勾选）

### 分端 / 分模块文档 `prd-{端}.md`

1. **端目标 / 范围**（单端版本：范围＝总览，只写引用与一句摘要，不复述）
2. **端内业务流程**：本端核心流程图 + 异常走向（错误码细节归操作清单与接口契约；跨端流程在总览）
3. **页面清单**（站点地图：页面名 + 路由 + 说明）
4. **页面详述**：每个页面一节，按「页面说明模板」；页面较多时**可按端内能力域拆为多个连续章节**（每域一章、域内仍逐页展开，后续章节号顺延，页面清单改名「页面与模块地图」标注所属域）
5. **后端 / 接口 / MQTT 详述**（非页面项单独成章，按「接口说明模板」）
6. **异常与空态汇总**
7. **验收 / 分端自查清单**（单端版本：与版本级自查一致时只写「无差异」，不重复填表）

**总览 / 分端分工（去重铁律）**：`prd.md` 只放**跨端共享**内容（术语 / 数据模型 / 状态机 / 跨端流程 / R 规则 / 验收与 DoD）；`prd-{端}.md` 放**该端全部细节**（端内流程 / 页面 / 接口 / 白名单等）。同一内容只允许一个定义处，另一处引用——禁止两边各写一份。

#### 全局组件章节（每端文档开头，定义一次）

多页共用的组件/交互只定义一次，页面内用 **【全局】** 引用，不重复描述。每个全局组件列：ID、组件、出现页面、展示信息、数据来源、操作、状态、动效。常见：顶部信息条、语言切换、网络/连接状态、Toast、Loading/骨架、底部悬浮条、错误/空态占位、页面切换手势。

#### 页面说明模板（逐页 · 组件级）

- **页面信息**：页面名 / 路由 / 入口 / 出口 / 前置条件
- **页面功能**：本页要完成的事（编号列举）
- **组件清单**（逐个组件一行，必含）：
  - ID、组件名、类型（卡片/列表/弹层/步进器…）
  - **作用域**：【局部】本页专有 / 【全局】引用全局组件 ID
  - 展示信息（该组件显示的内容）
  - 数据来源（字段 / 接口编号 / 前端态）
  - 操作（可对该组件做的动作）
  - 状态（默认/选中/禁用/空/加载/错误…）
  - 动效（时长 + 缓动 + 描述）
- **信息/数据字段**：本页展示的字段 → 来源
- **操作清单**（逐操作一行）：操作、触发、前置、结果、调用接口、反馈、异常
- **调用接口**：本页用到的接口编号（契约在接口章节）
- **动效清单**：动效、时长/缓动、说明
- **校验规则**（长度/类型/特殊字符/正则/上下限/必填）
- **计算逻辑**（如涉及，给公式）
- **状态与反馈**：默认/空态/加载/错误提示/成功反馈/无权限/数据极值
- **权限与可见性 / i18n（文案 key）/ 操作记录（是否留痕）**

#### 接口说明模板（非页面：后端 / 接口 / MQTT / 任务）

- **REST 接口**：方法 + 路径 + 作用 + 鉴权 + 入参/出参要点 + 幂等 + 主要错误码
- **MQTT 主题**：主题名 + 方向(pub/sub) + 触发时机 + payload 要点 + 订阅端 + QoS/重连策略
- **定时任务 / 后台作业**：触发 + 逻辑 + 幂等 + 失败处理

## 原型制作与预览约定

### 格式与定位

- 正式原型统一为 **HTML 中保真灰稿**（不用 SVG / Excalidraw / 设计图截图）：结构、组件、状态、文案为真，品牌视觉刻意不做——高保真视觉归「设计-高保真」责任端（联动 `3.DESIGN.md`）。
- 原型是**结构 / 交互契约**，同时面向三个读者：人（浏览器评审）、PRD（iframe 对照）、AI（生成生产代码的结构化输入）。
- 生产代码以 **原型 + PRD + `3.API.md`** 共同为输入，在目标技术栈重写（POS/KDS 为 Flutter，本就需翻译）；**禁止把原型代码直接搬入生产仓库**。

### 文件组织

- **存放**：`prototype/{端}/{页面}.html`；路径一律 ASCII（customer / mch / pos / kds / sys / ops / www / num），禁止中文。
- **仓库自包含，不允许跨仓库引用**（ADR-01）；版本间不互相引用原型文件。
- **无顶层 `prototypes/` 目录**。PRD 引用原型一律用**同级相对路径** `prototype/{端}/{页面}.html`（PRD 与 `prototype/` 同级）——**禁止 `../` 向上跨目录引用**（`../prototypes/`、`../../prototypes/` 等一律为缺陷）。
- **每屏一个 HTML 文件**，独立 URL，PRD 可 iframe 到具体那一屏；**禁止单文件 JS 状态翻屏**（无法深链）。
- 纯静态、零构建、**零外部依赖**（不引 CDN 框架/字体，断网可预览）；线框 CSS 放本版本 `prototype/assets/`，随版本各自维护。

### 状态与多语言

- 每屏覆盖全状态：默认 / 空态 / 加载 / 错误 / 极端值（超长文本、0/最大值），使用真实边界数据，不用占位文案。
- 每屏带**状态切换器**与**语言切换**（zh-CN / en-US / ms-MY）；ms-MY 长文案用于排版溢出验证（联动 `3.I18N.md`）。

### AI 可读性标注（机器可解析契约）

| 标注 | 约定 | 对应 |
|------|------|------|
| `data-comp` | 组件 ID，与 PRD 组件清单一致 | G1…（全局）/ C1…（局部） |
| `data-i18n` | 文案 key | 与翻译文件一一对应 |
| `data-state` | 显式状态枚举 | default / empty / loading / error / overflow |
| 文件头注释块 | 页面名 / 路由 / 对应 PRD 章节 / 涉及接口编号 | PRD ↔ 原型互查 |

### 预览方式

- **预览（Obsidian / 浏览器）**：在**仓库根目录**起静态服务，约定端口 **5500**（VSCode Live Server 默认，或 `python3 -m http.server 5500`），PRD 中用 `http://127.0.0.1:5500/prototype/...` 内联 `<iframe>`。
  - 用 `http://` 而非绝对 `file://`：不依赖 clone 路径，可移植（仅约定端口）。
  - 兜底链接用同版本相对路径 `prototype/{端}/{页面}.html`（PRD 与 prototype/ 同级）。
- **Codeup 网页端不渲染 iframe**（HTML 被净化）；若需在 Codeup 内看，改放**截图 PNG**（`![](img/xx.png)`）。
- 原型与 PRD 必须一致；不一致时以**正确方为准**对齐另一方。
